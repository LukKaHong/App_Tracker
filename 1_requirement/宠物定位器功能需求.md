## 1.工作模式

| 工作模式 | 联网                                | 定位频率                  | 说明                                                                                                                                                                                                        |
| ---- | --------------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 寻宠模式 | 保持mqtt连接，周期上报数据                   | 10秒/次                 | 1、通过平台下发指令进入此模式，进入此模式10分钟后自动切回到看护模式，避免长时间耗电。2、定位周期短，GNSS 保持供电（热启动），不执行断电流程；MCU 在定位间隙休眠。                                                                                                                   |
| 遛宠模式 | 保持mqtt连接，周期上报数据                   | 30秒/次                 | 1、通过平台下发指令进入此模式，进入此模式30分钟后自动切回到看护模式，避免长时间耗电。2、GNSS 保持供电（热启动），不执行断电流程；MCU 在定位间隙休眠。                                                                                                                         |
| 看护模式 | 保持mqtt连接，周期上报数据                   | 5分/次                  | 1、设备上电后自动进入此模式。2、可通过平台下发指令进入此模式。3、执行完整 LP 流程（GNSS 断电 + RTC 闹钟唤醒）。                                                                                                                                         |
| 省电模式 | 保持mqtt连接，周期上报数据                   | 1小时/次                 | 1、可通过平台下发指令进入此模式。2、执行完整 LP 流程（GNSS 断电 + RTC 闹钟唤醒）。3、定位周期间按 15 分钟心跳保活（见 6.3）。                                                                                                                              |
| 休眠模式 | 保持mqtt连接，不主动上报数据，收到平台的状态读取指令后上报数据 | 收到平台的状态读取指令后，才会进行一次定位 | 1、可通过平台下发指令进入此模式。2、处于超低电量的时候，上报一次状态事件，上报完成后强制切换到休眠模式。3、只有收到平台的状态读取指令后，才会进行一次定位，定位完成之后关闭定位功能，然后上报一次数据给平台。4、GNSS 保持关闭，按 30 分钟心跳保活（仅维持会话）；平台指令经网络寻呼即时唤醒设备，响应延迟为寻呼周期量级（秒级）。5、检测到充电（SOC 回升至 10% 以上）后自动恢复到看护模式。 |

需要考虑功耗的问题，在不进行定位的时候，模组需要进入低功耗LP模式。

**LP 完整流程仅适用于看护模式、省电模式**（寻宠/遛宠模式定位周期短于 GNSS 冷启动时间，GNSS 需保持热启动常开）。

| 模组进入LP模式步骤 | 说明                                                                                                                                                                                                | <br /> |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----- |
| step1      | 根据定位频率设置RTC闹钟唤醒（cm\_rtc\_set\_alarm）。                                                                                                                                                             | <br /> |
| step2      | 模组设置成LP模式，关闭GNSS电路电源（GPS\_PWR\_EN 拉低）；GPS UART RX/TX 引脚配置为睡眠态；Gsensor IIC（SDA/SCL）引脚配置为高阻浮空态——Gsensor 常供电持续计步，禁止拉低（否则电流经 IIC 上拉电阻持续漏电，约 380μA/线@1.8V/4.7kΩ）。引脚睡眠态配置统一使用 cm\_iomux\_set\_pin\_cmd。 | <br /> |
| step3      | 等待唤醒：RTC 闹钟（定位周期）、网络寻呼（平台下行指令即时唤醒）。                                                                                                                                                               | <br /> |
| step4      | 1、打开GNSS电路电源，开始读取GNSS芯片的定位信息。2、同时读取协议栈缓存的LBS基站参数（毫秒级，不阻塞）。3、（可选）静止省电判定（计步增量法，详见第 8 章）：连续 2 个定位周期静止时跳过本次 GNSS 定位（GNSS 保持断电），直接跳 step6 上报缓存坐标+LBS；若 LBS cellid 较上周期变化则不跳过。                          | <br /> |
| step5      | 等待GNSS定位完成，超时 90 秒判定 GNSS 无效（超时值为建议值，需按芯片冷启动实测调整）。                                                                                                                                                | <br /> |
| step6      | 上报数据给平台（GPS 数据与 LBS 参数均上报；GNSS 无效时 GPS 字段标记无效），跳转step1。若为平台指令寻呼唤醒，处理完指令后重新进入 LP，定位仍按 RTC 闹钟周期执行。                                                                                                  | <br /> |

## 2.定位功能

定位频率根据运行模式调整。

### 2.1 GNSS

定位需要获取当前的经纬度、卫星连接数、移动速度。

定位芯片型号为CC1161W，协议为NMEA 0183，使用串口进行通讯，波特率115200，8位数据位，1位停止位，无奇偶校验。

需解析的 NMEA 语句：

| 语句  | 用途                        |
| --- | ------------------------- |
| RMC | 经纬度、移动速度、UTC 时间、定位状态(A/V) |
| GGA | 卫星连接数、定位质量指示、HDOP         |

定位芯片的波特率要设置成跟串口波特率一样，一直尝试设置，尝试设置间隔为2秒，直到设置好为止。

> 注意：CC1161W 的波特率配置是否掉电保存需查阅芯片手册或向供应商确认：
>
> - 若支持保存，出厂时一次性配置即可；
> - 若不支持，每次 GNSS 上电后都需重新配置，LP 流程 step4 需预留配置时间。

GNSS 有效性判定：

- 单次定位有效：RMC 语句定位状态为 A（有效定位）。
- 看护/省电模式下单次定位超时 90 秒未获得有效定位，判定本次 GNSS 无效。
- 上次有效定位时间距今超过当前工作模式定位周期的 2 倍时，判定 GPS 无效，上报数据中 GPS 字段标记为无效（LBS 参数仍正常上报）。

### 2.2 LBS定位

定位器获取原始的基站参数上报给平台，平台再通过高德进行坐标解算。定位器不通过高德进行坐标解算，只上报参数给平台。

上报策略：

- **无论 GNSS 定位是否有效，每个定位周期都上报 LBS 参数**（平台可结合 GPS 与基站信息综合解算，提高定位可靠性）。
- LBS 参数采集跟随定位频率，每个定位周期采集一次（读取协议栈缓存，耗时毫秒级）。
- 如 SDK（cm\_modem\_get\_cell\_info）支持获取邻区信息，应一并上报以提高高德解算精度（需确认接口能力）。

基站参数：

| 字段     | 含义               |
| :----- | :--------------- |
| mcc    | 移动国家码            |
| mnc    | 移动网络号            |
| lac    | 位置区码（LTE 下即 TAC） |
| cellid | 小区编号（LTE 下即 ECI） |
| signal | 信号强度，**负数 dBm**  |

WIFI热点参数（**当前版本禁用**）：

> WiFi 扫描需关闭 LTE 射频（CFUN=5），实测导致 40\~90 秒离线，与"非关机模式下一直保持连接"的要求冲突，当前版本禁用（APP\_LBS\_WIFI\_ENABLE=0）。保留字段定义，如后续平台侧有强需求再评估开启。

| 字段     | 含义               |
| :----- | :--------------- |
| mac    | AP 的 MAC 地址，冒号分隔 |
| signal | RSSI，负数 dBm      |
| ssid   | 热点名称             |

详细的参数信息查阅高德智能硬件定位方法：<https://lbs.amap.com/api/webservice/guide/api-advanced/hardware-location>

## 3.按键功能

**电源键（硬件开关机）**：物理按键连接 PWR\_ON/OFF 管脚（Pin7），直接控制模组电源，软件无需干预：

- 模组关机状态下，长按 2s\~3.5s 开机；
- 模组开机状态下，长按 3.5s\~4s 后松开，执行关机流程；
- 软件**不注册** powerkey 回调（cm\_pm\_powerkey\_regist\_callback 传空），保持默认硬件开关机行为；
- 按键参考电路与 ESD 防护（TVS）要求见《ML307C\_硬件设计手册》开关机章节。

**KEY（Pin86，硬件预留）**：当前版本软件不实现，预留按键电路供后续版本启用，用途后续定义。启用时的设计要求（预先约定，避免返工）：

- LP 睡眠期间按键唤醒：通过 cm\_iomux\_set\_pin\_cmd 配置引脚 LPM 边沿检测（下降沿 LPM\_EDGE\_FALL）实现，SDK 接口已确认对任意 IOMUX 引脚开放（cm\_iomux.h PINCMD1），启用前需对 KEY 管脚实测验证。
- **ISR 中仅允许置位事件标志/释放信号量，禁止在 ISR 中打印日志、获取互斥锁、调用任何阻塞或 OSA 相关 API**；按键实际处理（计时、功能执行）在任务上下文完成。
- 按键防抖 50ms（任务上下文软件滤波）。

## 4.蜂鸣器功能

接收到平台下发的声音启动指令后，蜂鸣器每一秒响一次（单次鸣响 200ms），持续时间由平台下发，如持续时间内收到停止指令，停止蜂鸣。

设备处于 LP 睡眠时，平台指令经网络寻呼即时唤醒设备（秒级，见 6.3）；仅在设备脱网时需等待唤醒后重连才能执行。

## 5.指示灯

接收到平台下发的指示灯启动指令后，持续快闪（5Hz，建议值），持续时间由平台下发，如持续时间内收到停止指令，停止快闪。

常态指示行为（建议值，可调整）：

| 状态           | 指示灯行为      |
| ------------ | ---------- |
| 未联网          | 快闪（5Hz）    |
| 已联网正常工作      | 慢闪（每3秒闪一次） |
| 低电量（SOC<20%） | 每秒双闪       |
| 休眠/LP睡眠      | 熄灭         |

## 6.联网功能

### 6.1离线重连

设备开机后，需一直与平台保持连接，如遇到断线情况，按退避策略反复尝试重连：

- 重连间隔按 5s → 10s → 30s → 60s 递增，封顶 60s；重连成功后重置退避间隔。
- 看护/省电模式下连续重连失败 5 次后，停止重连并进入 LP 睡眠，等待下一定位周期再尝试，避免弱网环境持续耗电。

### 6.2离线补传

与平台断开连接后，需要缓存上报给平台的数据，与平台恢复连接后，要补传离线期间的数据，缓存的数据最大条数为30，当数据条数大于最大条数时，删除最早的数据。

每条缓存数据必须携带定位采集时刻的 UTC 时间戳（RTC 时间），平台据此还原定位时序。

离线数据重启定位器后可丢失，不做落盘处理。

### 6.3 MQTT 心跳、唤醒源与下行指令响应

依据《ML307C\_电源管理开发指导手册》，LP 模式为模组系统级睡眠：**睡眠期间协议栈保持网络注册并监听寻呼，TCP/MQTT 连接不断开，唤醒后无需重建连接**。

LP 睡眠唤醒源：

| 唤醒源        | 说明                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------- |
| 网络寻呼（下行数据） | 平台下发 MQTT 指令时，网络侧寻呼即时唤醒模组（唤醒原因 WAKEUP0(GSM)），应用层经 MQTT 回调接收指令；响应延迟为寻呼周期量级（DRX 周期由网络侧配置，需实测），处理完成后自动重新进入 LP |
| RTC 闹钟     | 按当前模式定位周期设置的周期唤醒（cm\_rtc\_set\_alarm），执行定位与上报                                                              |

心跳与保活（心跳仅用于维持运营商 NAT 映射和 broker MQTT 会话，与接收平台指令无关）：

| 工作模式 | 心跳/保活方式                         |
| ---- | ------------------------------- |
| 寻宠模式 | 定位上报即保活（MQTT keepalive 建议 120s） |
| 遛宠模式 | 定位上报即保活（MQTT keepalive 建议 120s） |
| 看护模式 | 定位上报即保活（MQTT keepalive 建议 600s） |
| 省电模式 | 每 15 分钟一次心跳（定位周期间插入唤醒）          |
| 休眠模式 | 每 30 分钟一次心跳                     |

说明：

- 平台下发的实时性指令（模式切换、蜂鸣、指示灯、状态读取）在设备 LP 睡眠期间由**网络寻呼即时唤醒执行**，延迟为寻呼周期量级；仅在设备脱网（弱信号/掉线）时，需等待设备定时唤醒重连后才能接收。
- 心跳间隔必须小于运营商 NAT 超时与 MQTT keepalive，否则连接被网络侧拆除，需实测确定下限；在此之上可尽量拉长以降低功耗。
- 进入 LP 的前提：全部任务退出运行状态（阻塞等待事件）、无未释放的睡眠锁（cm\_pm\_work\_lock/unlock）、未外接 USB。

### 6.4 OTA功能

支持ML307固件远程更新，使用全系统差分升级方案。

要求：

- 升级过程具备断电保护（断点续传或双区备份），断电重启后可恢复升级。
- 升级失败自动回滚到旧版本，不允许变砖。
- 升级完成后上报新版本号。

版本校验规则见 6.7。

### 6.5 对时机制

- MQTT 连接成功后向平台同步时间（平台下发时间戳或使用网络时间），此后每天对时一次，误差超限时重新对时。
- 时区固定 UTC+8。
- 计步清零、离线数据时间戳均依赖该时间，对时成功前计步不做 0 点清零。

### 6.7 软件版本管理

**版本号体系**：

| 版本       | 格式                   | 说明                           |
| -------- | -------------------- | ---------------------------- |
| APP 软件版本 | V主.次.修（如 V1.0.3）     | 主版本=协议/架构变更，次版本=新功能，修订号=缺陷修复 |
| 硬件版本     | HW\_V主.次（如 HW\_V1.0） | 跟随 PCB 版本，引脚分配变更必须升硬件版本      |

- 版本号编译期注入固件（app\_config.h 宏定义），运行时可读。
- 基带固件版本（ML307C 系统版本）经 SDK 接口读取，随设备信息上报，便于区分问题归属（app 层/基带层）。

**版本上报**：

- 上线主动上报：MQTT 连接成功后上报设备信息事件，携带 app\_ver、hw\_ver、modem\_ver、imei、iccid。
- 平台查询：平台下发版本查询指令，设备应答当前版本信息。
- OTA 结果确认：升级重启后首条消息上报新版本号（升级成功凭据）；回滚则上报旧版本与失败原因。

**OTA 版本校验**（设备收到升级指令后依次校验，任一不通过则拒绝升级并上报原因）：

1. 硬件版本匹配：升级包标注适用硬件版本，不匹配拒绝（防止刷入引脚配置不符的固件）。
2. 源版本匹配：差分包基于特定源版本生成，设备当前版本与差分包源版本不一致时拒绝。
3. 防降级：目标版本低于或等于当前版本时拒绝，平台下发强制标志除外。
4. 包完整性校验：MD5/CRC 校验（见 6.4）。

**硬件版本识别**：产测时将硬件版本写入 flash 固定区域（生产烧录写入），固件启动时读取，用于初始化对应引脚配置及 OTA 校验。

**平台配套**：平台维护设备版本台账（设备 ID → 当前版本），OTA 按版本分批灰度推送；每版本归档差分包、全量包与发布说明。

## 7.电量计算

通过电池电压估算SOC，通过主控的ADC检查电压（开路电压查表法，放电曲线需实测标定）。

SOC小于20%为低电量状态。

SOC小于5%为超低电量状态：上报一次状态事件后强制切换到休眠模式。

充电检测（硬件已具备充电状态检测脚 CHRG\_State，pin87，高电平=充电中、低电平=非充电中）：

- 检测充电状态（充电中/已充满）并上报平台，充电状态变化时即时上报。
- 检测方式：GPIO 电平轮询（随定位/心跳周期读取）；若硬件将检测脚接至支持 LP 边沿唤醒的 GPIO，LP 睡眠期间插入充电可即时唤醒处理。
- 休眠模式下检测到充电（或 SOC 回升至 10% 以上）后自动恢复到看护模式。

## 8.宠物计步

加速度传感器型号QMA6100P。

经查阅《QMA6100P\_规格书》确认，芯片内置计步器（Built-in motion algorithm），本方案使用内置计步功能实现，软件要点如下：

- 使能：STEP\_EN（寄存器 0x12 bit7）置 1，启用内置计步器。
- 读数：STEP\_CNT 为 24bit 计步寄存器（0x07 低 8 位、0x08 中 8 位、0x0E 高 8 位），主控唤醒后经 IIC 读取。
- 清零：STEP\_CLR（寄存器 0x13 bit7）清零计数值，用于每天 0 点清零。
- 算法参数：寄存器 0x12\~0x15（STEP\_CONF0\~3）、0x1D\~0x1F（STEP\_CFG0\~2），初版使用手册默认值，按实测效果微调。
- 中断：STEP\_INT（0x0A<3>）/SIG\_STEP（0x0A<6>）可映射至 INT1/INT2 引脚；若中断脚未连接，软件按定位周期轮询读取计数值即可。
- 功耗：计步需芯片处于 Low power 测量模式，ODR=80Hz 时电流约 5μA（手册电气特性表），主控 LP 睡眠期间由 Gsensor 持续累计步数。

统计每天的步数，步数每天本地时间0点清零（依赖 6.5 对时机制）。

步数随定位数据一并上报平台。

（可选优化）看护/省电模式静止省电，判定方法与行为如下：

- **判定方法（计步增量法）**：每个定位周期唤醒时读取 STEP\_CNT 并与上周期比较，步数增量 ≤ 3 步（阈值可配置）判定本周期静止；**连续 2 个定位周期**静止，判定宠物处于静止状态。
- **静止期间行为**：跳过 GNSS 定位（GNSS 保持断电，不执行 LP 流程 step4 的开电动作），直接上报缓存坐标与 LBS 参数。
- **LBS 安全网（防被动移动漏检）**：静止期间比较本周期与上周期 LBS cellid，若 cellid 变化（跨基站，说明设备在移动，如被抱着走/乘车），立即恢复正常 GNSS 定位。
- **恢复**：任一周期步数增量超阈值或 cellid 变化，下个周期起恢复正常 GNSS 定位。
- 该优化可通过平台配置开关关闭。

## 9.异常处理与看门狗

- 开启硬件看门狗，任务异常无法喂狗时自动复位。
- 当前工作模式掉电保存（flash）：看门狗等异常复位后，自动恢复到复位前的工作模式并重新联网；首次上电默认进入看护模式。
- LP 睡眠期间若网络脱网，平台下行指令不可达；设备按闹钟/心跳周期唤醒后检测到掉线，按 6.1 退避策略重连并补收指令。
- 重启后读取复位原因，异常复位事件上报平台，便于远程问题定位。
