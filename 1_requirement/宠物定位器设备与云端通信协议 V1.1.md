## 1. 设备首次入网：注册并获取 MQTT 登录信息

设备本地没有有效 MQTT 登录信息时调用：

```http
POST {SAAS_BASE_URL}/api/device/v1/provision
Content-Type: application/json
```

请求：

```json
{
  "imei": "860000000000000",
  "device_sn": "860000000000000",
  "model_code": "PET-LTE-001",
  "firmware_version": "1.0.0",
  "protocol_version": "v1",
  "timestamp": "2026-09-05T10:00:00Z",
  "nonce": "nonce-0001",
  "signature": "hex_or_base64_hmac_sha256"
}
```

| 字段                 | JSON 类型 | 必填   | 规则                                            |
| ------------------ | ------- | ---- | --------------------------------------------- |
| `imei`             | string  | 条件必填 | 与 `device_sn` 至少提供一个；禁止使用 JSON number。        |
| `device_sn`        | string  | 条件必填 | 与 `imei` 至少提供一个；V1 等于 IMEI，禁止使用 JSON number。  |
| `model_code`       | string  | 是    | 必须与平台导入的型号一致。                                 |
| `firmware_version` | string  | 否    | 当前固件版本。                                       |
| `protocol_version` | string  | 否    | V1 建议填 `v1`。                                  |
| `timestamp`        | string  | 是    | RFC3339/RFC3339Nano；推荐 UTC `Z`，默认允许前后 5 分钟偏差。 |
| `nonce`            | string  | 是    | 每次请求使用新随机值。                                   |
| `signature`        | string  | 是    | 所属型号一型一密 secret 的 HMAC-SHA256 摘要。             |

签名前 trim 各字段，按以下顺序用 `\n` 连接；空可选字段仍保留空值行，末尾不加换行：

```text
imei={imei}
device_sn={device_sn}
model_code={model_code}
firmware_version={firmware_version}
protocol_version={protocol_version}
timestamp={timestamp}
nonce={nonce}
```

`signature = HMAC_SHA256(canonical_string, provisioning_secret)`。签名支持 hex、
base64 和无 padding base64，推荐小写 hex。

成功响应：

```json
{
  "data": {
    "mqtt_host": "mqtt.example.com",
    "mqtt_port": 8883,
    "client_id": "860000000000000",
    "username": "tb_access_token",
    "password": "",
    "credential_type": "ACCESS_TOKEN",
    "issued_at": "2026-09-05T10:00:01Z"
  },
  "request_id": "req_123"
}
```

设备保存 `data` 中全部参数。V1 的 `credential_type` 固定为 `ACCESS_TOKEN`，
`password` 为空字符串。重新注册必须使用新 `nonce`。

必要错误码：`VALIDATION_ERROR`、`INVALID_DEVICE_SIGNATURE`、`DEVICE_NOT_FOUND`、
`DEVICE_NONCE_REPLAY`、`DEVICE_MODEL_MISMATCH`、`DEVICE_NOT_IN_TENANT`、
`DEVICE_FROZEN`、`DEVICE_VOIDED`、`INVALID_DEVICE_STATUS`。只有
`DEVICE_NONCE_REPLAY` 可在更换 nonce 后立即重试；网络错误使用退避重试。

一型一密 secret、MQTT 登录信息和签名不得写入普通日志；生产连接必须使用 TLS。

## 2. MQTT 连接和 Topic

| 参数                  | 使用值                                                            |
| ------------------- | -------------------------------------------------------------- |
| Host / Port         | `data.mqtt_host` / `data.mqtt_port`                            |
| Client ID           | `data.client_id`                                               |
| Username / Password | `data.username` / `data.password`                              |
| 协议                  | MQTT 3.1.1                                                     |
| Keepalive           | 按工作模式：寻宠/遛宠 120 秒；看护/省电/休眠 600 秒（连接建立时生效）                      |
| QoS                 | telemetry 上报和 RPC 订阅使用 QoS 1；ThingsBoard RPC response 使用 QoS 0 |

| 方向       | Topic                                    | 用途                                      |
| -------- | ---------------------------------------- | --------------------------------------- |
| 设备 -> 云端 | `v1/devices/me/telemetry`                | 上报 `location`、`state`、`command_result`。 |
| 云端 -> 设备 | `v1/devices/me/rpc/request/+`            | 接收服务端 RPC。                              |
| 设备 -> 云端 | `v1/devices/me/rpc/response/{requestId}` | 回 ThingsBoard RPC 闭环（非业务结果）。            |

连接成功后先订阅 RPC Topic，再上报 `ONLINE`。重连后必须重新订阅。

## 3. 设备上报数据

所有报文 publish 到 `v1/devices/me/telemetry`，payload 是单个 JSON object。
时间使用 RFC3339/RFC3339Nano，推荐 UTC `Z`。设备不得上报 `tenant_id` 或
`device_id`。

### 3.1 定位 `location`

所有定位相关数据使用**同一报文格式**（`event_type=location`）：设备按实际采集结果携带字段，未采集或无效的字段省略，平台按字段有无解析，不要求固定字段组合。同一周期数据可拆分多帧上报，每帧均为下表字段子集。

全字段示例：

```json
{
  "event_type": "location",
  "message_id": "loc_860000000000000_boot001_1024",
  "imei": "860000000000000",
  "device_sn": "860000000000000",
  "event_time": "2026-09-05T10:00:00Z",
  "longitude": 121.4737,
  "latitude": 31.2304,
  "coordinate_system": "WGS84",
  "accuracy": 12.0,
  "source": "MIXED",
  "battery_level": 82,
  "network_type": "LTE",
  "signal_strength": -72,
  "speed": 1.4,
  "heading": 128.0,
  "altitude": 8.5,
  "satellite_count": 8,
  "bts": "460,0,34250,1234567,-85",
  "nearbts": "460,0,34250,7654321,-95|460,0,34251,1122334,-101",
  "macs": "AA:BB:CC:DD:EE:FF,-72|11:22:33:44:55:66,-88",
  "steps": 3200,
  "boot_id": "boot001",
  "sequence_no": 1024,
  "is_offline_upload": false
}
```

| 字段                       | JSON 类型 | 携带条件          | 规则 / 单位                                                          | <br />                         |
| ------------------------ | ------- | ------------- | ---------------------------------------------------------------- | :----------------------------- |
| `event_type`             | string  | 总是            | 固定 `location`。                                                   | <br />                         |
| `message_id`             | string  | 总是            | 幂等 ID；重传时保持不变。                                                   | <br />                         |
| `imei` / `device_sn`     | string  | 总是            | 至少一个；V1 建议两者都传且相同。                                               | <br />                         |
| `event_time`             | string  | 总是            | 定位实际产生时间。                                                        | <br />                         |
| `longitude` / `latitude` | number  | GNSS 定位有效时    | 经度 `[-180,180]`；纬度 `[-90,90]`。GNSS 无效时省略。                        | <br />                         |
| `coordinate_system`      | string  | 携带经纬度时        | `WGS84` 或 `GCJ02`；省略按 `WGS84`。                                   | <br />                         |
| `accuracy`               | number  | 有则携带          | 米。                                                               | <br />                         |
| `source`                 | string  | 总是            | 本帧携带的定位数据来源：`GPS`、`LBS`、`WIFI`、`MIXED`。                          | <br />                         |
| `battery_level`          | integer | 有则携带          | 百分比，`0-100`。                                                     | <br />                         |
| `network_type`           | string  | 有则携带          | 例如 `LTE`。                                                        | <br />                         |
| `signal_strength`        | integer | 有则携带          | dBm。                                                             | <br />                         |
| `speed` / `altitude`     | number  | 有则携带          | m/s / 米。                                                         | <br />                         |
| `heading`                | number  | 有则携带          | 度，`[0,360)`。                                                     | <br />                         |
| `satellite_count`        | integer | GNSS 有效时      | 卫星连接数。                                                           | <br />                         |
| `bts`                    | string  | 每定位周期采集，基站可用时 | 服务小区 `mcc,mnc,lac,cellid,signal`；signal 为负数 dBm。无论 GNSS 是否有效均上报。 | <br />                         |
| `nearbts`                | string  | 邻区可用时         | 邻区列表，组内格式同 `bts`，组间以 \`                                          | \` 分隔；可能为空串。                   |
| `macs`                   | string  | WiFi 扫描完成后    | WiFi AP 列表 `MAC,rssi`，组间以 \`                                     | \` 分隔；MAC 大写冒号分隔，rssi 为负数 dBm。 |
| `steps`                  | integer | 有则携带          | 当日累计步数，本地 0 点清零。                                                 | <br />                         |
| `boot_id`                | string  | 总是            | 本次启动周期 ID。                                                       | <br />                         |
| `sequence_no`            | integer | 总是            | 同一 `boot_id` 内单调递增。                                              | <br />                         |
| `is_offline_upload`      | boolean | 总是            | 实时为 `false`，断网补传为 `true`。                                        | <br />                         |

### 3.2 设备状态 `state`

```json
{
  "event_type": "state",
  "message_id": "state_860000000000000_boot001_42",
  "imei": "860000000000000",
  "device_sn": "860000000000000",
  "online_status": "ONLINE",
  "event_time": "2026-09-05T10:00:00Z",
  "battery_level": 82,
  "firmware_version": "1.0.1",
  "network_type": "LTE",
  "signal_strength": -72,
  "mode": "searching",
  "charging_status": 0
}
```

| 字段                                  | JSON 类型 | 必填 | 规则 / 单位                                                                       |
| ----------------------------------- | ------- | -- | ----------------------------------------------------------------------------- |
| `event_type`                        | string  | 是  | 固定 `state`。                                                                   |
| `message_id`                        | string  | 建议 | 幂等 ID；重传时保持不变。                                                                |
| `imei` / `device_sn`                | string  | 是  | 至少一个，必须是 JSON string。                                                         |
| `online_status`                     | string  | 是  | `ONLINE`、`OFFLINE`、`STALE`。                                                   |
| `event_time`                        | string  | 是  | 状态实际产生时间。                                                                     |
| `battery_level`                     | integer | 否  | 百分比，`0-100`。                                                                  |
| `firmware_version` / `network_type` | string  | 否  | 固件版本 / 网络类型。                                                                  |
| `signal_strength`                   | integer | 否  | dBm。                                                                          |
| `mode`                              | string  | 是  | 当前设备运行模式：`searching` 寻宠、`walking` 遛宠、`supervise` 看护、`lowpower` 省电、`sleep` 休眠。 |
| `charging_status`                   | integer | 否  | 充电状态：`0` 非充电中，`1` 充电中；充电状态变化时随状态事件上报。                                         |
| `hw_version`                        | string  | 否  | 硬件版本                                                                          |
| `modem_version`                     | string  | 否  | 基带固件版本                                                                        |

### 3.3 指令结果 `command_result`

成功：

```json
{
  "event_type": "command_result",
  "message_id": "cmd_result_cmd_uuid_ACKNOWLEDGED",
  "command_id": "cmd_uuid",
  "status": "ACKNOWLEDGED",
  "event_time": "2026-09-05T10:00:12Z"
}
```

失败：

```json
{
  "event_type": "command_result",
  "message_id": "cmd_result_cmd_uuid_FAILED",
  "command_id": "cmd_uuid",
  "status": "FAILED",
  "event_time": "2026-09-05T10:00:12Z",
  "failure_code": "ACTUATOR_FAULT",
  "failed_reason": "speaker start failed"
}
```

| 字段              | JSON 类型 | 必填          | 规则                             |
| --------------- | ------- | ----------- | ------------------------------ |
| `event_type`    | string  | 是           | 固定 `command_result`。           |
| `message_id`    | string  | 是           | 幂等 ID；重传时保持不变。                 |
| `command_id`    | string  | 是           | 原样使用下行 `params.command_id`。    |
| `status`        | string  | 是           | 只发送 `ACKNOWLEDGED` 或 `FAILED`。 |
| `event_time`    | string  | 是           | 结果产生时间。                        |
| `failure_code`  | string  | `FAILED` 时是 | 稳定的大写蛇形错误码。                    |
| `failed_reason` | string  | 否           | 简短诊断，不得包含凭证或隐私。                |

## 4. 设备接收和执行指令

Topic：

```text
v1/devices/me/rpc/request/{requestId}
```

Topic 中的 `requestId` 只是 ThingsBoard 投递标识，不是业务 ID。设备执行、去重和
结果关联只使用 `params.command_id`，两者不得混用。

```json
{
  "method": "SOUND",
  "params": {
    "command_id": "cmd_uuid",
    "duration_seconds": 30
  }
}
```

`method` 是必填大写字符串；`params` 是必填 object；`params.command_id` 是必填
非空字符串。其他参数可省略，显式值校验通过后优先于默认值，未知字段忽略。
快捷指令可能只有 `command_id`，设备必须使用下表默认值。

### 4.1 method 和默认参数

| `method`      | 参数和默认值                              | 行为                                                                               |
| ------------- | ----------------------------------- | -------------------------------------------------------------------------------- |
| `SOUND`       | `duration_seconds=30`；`0` 表示停止，负数非法 | 启动声音\*\*，\*\*持续 duration 秒后自动关闭。                                                 |
| `LIGHT`       | `duration_seconds=30`；`0` 表示停止，负数非法 | 启动灯效，持续 duration 秒后自动关闭。                                                         |
| `DEVICE_MODE` | `mode` 必填                           | 切换设备运行模式。`searching` 寻宠、`walking` 遛宠、`supervise` 看护、`lowpower` 省电、`sleep` 休眠。    |
| `GET_STATE`   | 无                                   | 应答携带完整设备信息的状态事件（3.2 节，含 `hw_version`/`modem_version`/`iccid` 等）。休眠模式下同时作为状态读取指令。 |
| `OTA`         | `url` 必填，非空字符串                      | 启动固件升级下载。升级指令处理中重复下发回 `DEVICE_BUSY`。                                             |

### 4.2 工作模式与定位周期

各工作模式的默认定位周期与保活方式：

| 工作模式           | 定位/上报周期                | 保活方式           |
| -------------- | ---------------------- | -------------- |
| 寻宠 `searching` | 10 秒/次                 | 定位上报即保活        |
| 遛宠 `walking`   | 30 秒/次                 | 定位上报即保活        |
| 看护 `supervise` | 5 分钟/次                 | 定位上报即保活        |
| 省电 `lowpower`  | 1 小时/次                 | 定位周期间每 15 分钟心跳 |
| 休眠 `sleep`     | 不主动上报；收到状态读取指令后单次定位+上报 | 每 30 分钟心跳      |

## 5. ACK、幂等、补传和失败码

- 每个 `command_id` 只产生一个终态结果。`ACKNOWLEDGED` 表示动作已成功启动或
  配置已生效，不表示定时动作已经结束；自然结束时不再上报第二条结果。
- 指令按 `command_id` 去重。重复指令不重复执行，只重发已保存的同一结果。
- `command_result` 以 QoS 1 上报。
- 断网定位保留原 `event_time`、`message_id`、`boot_id`、`sequence_no`，设置
  `is_offline_upload=true`，按采集顺序限速补传（缓存 30 条，超出丢弃最早，
  限速 5 条/秒）。旧点不得覆盖较新的最新位置。仅含 `bts`/`nearbts`/`macs`
  原始参数的定位帧例外：断网直接丢弃，不缓存（见 3.1）。
- 定位优先按 `message_id` 去重；没有时使用 `boot_id + sequence_no + event_time`。
- WiFi 扫描窗口（约 37 秒、最小间隔 5 分钟）内 MQTT 短暂断开，平台下行指令
  延迟至重连后处理。

| `failure_code`                | 场景                                  |
| ----------------------------- | ----------------------------------- |
| `UNSUPPORTED_COMMAND`         | 不支持 `method`。                       |
| `INVALID_PARAMETER`           | 参数缺失、类型错误或超出范围。                     |
| `UNSUPPORTED_PARAMETER`       | 不支持参数值，例如 `DEVICE_MODE` 的未知 `mode`。 |
| `DEVICE_BUSY` / `LOW_BATTERY` | 设备状态或电量不允许执行。                       |
| `GPS_UNAVAILABLE`             | 无法启动定位。                             |
| `ACTUATOR_FAULT`              | 蜂鸣器、灯或驱动异常。                         |
| `STORAGE_ERROR`               | 去重记录或结果无法持久化。                       |
| `SHUTDOWN_REJECTED`           | 当前状态不允许安全关机。                        |
| `INTERNAL_ERROR`              | 其他固件内部错误。                           |
