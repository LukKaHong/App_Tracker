ML307C WiFi Scan 操作过程

目标：在不关闭 4G 通信的前提下，稳定执行 WiFi 扫描（WIFI_SCAN）
依据：硬件设计手册(AT版) V1.1.1 + WiFi-SCAN用户手册_4G系列适用_V1.2.2（命令来源）
⚠ 适用型号提示（重要）：WiFi-SCAN 用户手册 V1.2.2 的“适用型号表（Table 1）”列的是 ML302A / ML305A / ML307A / ML307R / ML307H / ML307N / ML307Y，未包含 ML307C。 但硬件设计手册 3.10 已确认 ML307C 支持 WIFI_SCAN 且共用 ANT_MAIN 天线，且 AT+MWIFISCANxxx 为同一厂商 4G 系列通用命令体系，命令名可直接采用。 ML307C 专属的 priority/hidden/round/timeout 取值范围、以及“是否允许在 4G 连接态扫描”等约束，需上机用 AT+MWIFISCANCFG=? / AT+MWIFISCANSTART=? 实测确认（下文用手册默认值并标注 ML307C 待核项）。
核心约束（来自硬件手册 3.10 + WiFi-SCAN 手册 3.2 注3）：ML307C 只有一路 RF（ANT_MAIN），WiFi Scan 与 4G 共用天线，模块内部对天线时分复用。 手册明确：“由于共用天线，建议在 IDLE 态下执行 WiFi-SCAN 扫描操作”。因此“不关 4G 又想 scan 稳”的本质 = ① 设 priority=0 让 LTE 优先；② 把 scan 排在 4G 空闲（IDLE/RRC 无数据传输）间隙；③ 降频+合并减少天线切换。

一、WiFi Scan AT 命令体系（真实）

命令功能语法 / 关键参数ML307C 说明
AT+MWIFISCANCFG配置扫描参数 "hidden",<hd_enable>：0/1，是否扫隐藏WiFi（默认0）
"priority",<priority>：0=LTE优先（默认）/ 1=WiFi优先
"max",<maxCount>：一次最大扫描数量（默认5）
只发 AT+MWIFISCANCFG="xxx" 返回当前配置		priority 是共存关键；范围/是否支持以 =? 为准
AT+MWIFISCANSTART启动扫描 AT+MWIFISCANSTART=<round>[,<timeout>[,<ssid>[,<channel>]]]
<round>：扫描轮次 1~3（默认3）
<timeout>：超时 s（默认60）
<channel>：指定通道；255=全通道（默认）
结果异步通过 +MWIFISCANINFO 上报		round/timeout 取值范围以 =? 为准；全通道=255 耗时较长
+MWIFISCANINFO扫描结果 URC +MWIFISCANINFO: <round>,<index>[,<SSID>,<BSSID>,<encryption>,<rssi>,<channel>,<is_hidden>]
index=0 代表扫描结束		通用，ML307C 适用
AT+MWIFISCANSTOP中断扫描超时未到或结果未返回时，可中断流程通用
AT+MWIFISCANQUERY查历史结果查询模组保留的“最近一次”扫描结果通用
📌 命令级共存保障：AT+MWIFISCANCFG="priority",0（LTE 优先，默认值）是“不关闭 4G 也稳定 scan”的第一道保险——它让 4G 业务在天线仲裁中优先，scan 不会抢占正在进行的 4G 收发。除非你明确需要 scan 优先（会牺牲 4G 流畅度），否则保持 priority=0。

二、不关 4G 的时序优化原则

  • LTE 优先保持 AT+MWIFISCANCFG="priority",0（默认即 LTE 优先），让 4G 在天线仲裁中占先。
  • IDLE 态扫描严格按手册注3：共用天线，建议在 IDLE 态（无 4G 数据传输的空闲间隙 / DRX 寻呼间隙）执行 scan，避开 TCP 重传、心跳临界、大包传输。
  • 缩小扫描面默认 channel=255 全通道扫描耗时最长；若已知目标信道，指定 <channel> 可显著缩短单次占用，更快把天线还给 4G。
  • 降频合并设最小 scan 间隔 ≥ 4G 业务周期若干倍；多次短 scan 在 MCU 侧缓存合并，减少天线切换次数。
  • 全程在线严禁为 scan 执行 AT+CFUN=0（那会断网）；保持 CFUN=1 且 CEREG? 已注册。

三、详细操作步骤（单次稳定扫描序列）

① 确认命令可用 & 读取当前配置：
AT+MWIFISCANSTART=? → 确认 ML307C 支持本命令及参数范围
AT+MWIFISCANCFG="priority" → 查当前优先级（应为 0=LTE优先）
② 设 LTE 优先（共存保障）：
AT+MWIFISCANCFG="priority",0 → OK（如 ML307C 支持该子项；不支持则跳过，默认即 LTE 优先）
③ 锁定 4G 在线基线：
AT+CFUN? → 期望 +CFUN: 1
AT+CEREG? → 期望已注册（1/5）
AT+CSQ → 记录信号基线
④ 配置扫描规模（按需）：
AT+MWIFISCANCFG="max",5 → 最大扫描数量（默认5）
AT+MWIFISCANCFG="hidden",0 → 不扫隐藏网络（提速，按需改1）
AT+MWIFISCANCFG="channel",<ch> → 指定信道（可选，省时）
⑤ 确认处于 4G 空闲窗口并启动扫描：确保当前不在 4G 数据传输中（应用层判断业务间隙）。
AT+MWIFISCANSTART=3 → OK（3 轮，默认超时 60s）
模块将天线切给 WiFi 监听，异步上报结果。
⑥ 读取扫描结果：监听串口 URC，直到 index=0 表示结束：
+MWIFISCANINFO: 1,,"CC08FB9DC5FB",,-79,1,
+MWIFISCANINFO: 2,,"20579EF9939A",,-87,7,
+MWIFISCANINFO: 0 ← 扫描结束
（结果也可稍后用 AT+MWIFISCANQUERY 二次查询）
⑦ 立即校验 4G 链路 & 健康闭环：
AT+CEREG? → 仍为注册态；AT+CSQ → 信号未暴跌
若掉网：先等网络自愈，必要时 AT+CFUN=1 兜底重注（恢复在线，非关闭通信）。
用 DBG_UART 抓 LOG / USB 看吞吐，对比扫描前后掉线率，迭代 scan 间隔与信道。
稳定判定：每次扫描均完整返回 AP 列表（到 +MWIFISCANINFO: 0），且扫前扫后 CEREG? 始终注册、CSQ 无骤降 —— 即“不关 4G 也稳定 scan”达成。

五、手册参考示例（可照搬序列）

// 配置（按需）
AT+MWIFISCANCFG="max",5        // 最大扫描数量
AT+MWIFISCANCFG="priority",0     // LTE 优先（不关 4G 的保障）
// 启动（在 4G 空闲窗口下发）
AT+MWIFISCANSTART=3           // 3 轮扫描，默认超时 60s
+MWIFISCANINFO: 1,,"CC08FB9DC5FB",,-79,1,
+MWIFISCANINFO: 2,,"20579EF9939A",,-87,7,
+MWIFISCANINFO: 0            // index=0 扫描结束
// 校验 / 二次查询
AT+CEREG?                     // 应仍为已注册
AT+MWIFISCANQUERY             // 查最近一次结果

六、注意事项与 ML307C 实测确认清单

  • 型号差异WiFi-SCAN 手册 V1.2.2 适用表未含 ML307C；命令体系通用，但 ML307C 的 priority/hidden/round/timeout 取值与“是否允许连接态扫描”需上机 AT+MWIFISCANSTART=? / AT+MWIFISCANCFG=? 实测。
  • LTE 优先保持 priority=0；除非确需 scan 优先，否则不要设 1（会让 4G 让路、影响通信）。
  • IDLE 态共用天线，扫描尽量排在 4G 无数据传输的空闲间隙；ML307H/ML307Y 明确“不支持连接态扫描”，ML307C 是否允许连接态以实测为准。
  • 省时技巧指定 <channel> 替代默认全通道(255) 可缩短单次扫描、更快归还天线给 4G。
  • 异步结果扫描结果经 +MWIFISCANINFO 异步上报，index=0 结束；可另用 AT+MWIFISCANQUERY 查询历史。
